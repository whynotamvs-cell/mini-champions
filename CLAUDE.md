# CLAUDE.md — постоянные инструкции проекта MINI CHAMPIONS

Этот файл читается в начале каждой сессии. Он короткий намеренно: детали — в `PROJECT_PLAN.md` и `docs/`.

## Что это за проект

MINI CHAMPIONS — семейная Roblox-игра. **Миниатюрный спортивный мир:** игроки крошечные, спортивные площадки построены на огромных предметах повседневной жизни (письменный стол, книги, карандаши, позже — кухня и другие окружения).

Текущий этап: **масштабирование обби** (решение владельца, ноябрь 2026): только жанр обби, но трассы длиннее и выше, физика клавиш, лазеры, больше анимаций, затем монетизация. Мини-игры других жанров по-прежнему не начинать без согласования.

## Инструменты

- Rojo (синхронизация с Studio), Git, VS Code, Roblox Studio.
- Rokit управляет версиями CLI-инструментов (`rokit.toml`).
- Selene — линтер, StyLua — форматирование, Luau LSP — типы и автодополнение в VS Code.
- Wally — только для dev-зависимостей (Jest-Lua). ProfileStore хранится в репозитории как закреплённая копия (vendored).

Типовые команды:

```bash
rokit install                    # установить инструменты из rokit.toml
rojo serve                       # синхронизация с Studio
rojo sourcemap --watch -o sourcemap.json   # для Luau LSP
selene src                       # линт
stylua --check src               # проверка форматирования
stylua src                       # форматирование
rojo build -o build/MiniChampions.rbxl     # сборка place-файла
lune run tests/lune/run.luau     # юнит-тесты tests/specs + проверка локализации (без Studio)
./tools/typecheck.sh             # строгая проверка типов (luau-lsp analyze)
python3 tools/gen_world.py       # перегенерировать серую геометрию world/*.model.json
```

## Жёсткие правила

1. **Сервер авторитетен.** Валюта, награды, покупки, результаты забегов, прогресс — только сервер. Клиент присылает намерения («хочу купить X»), а не результаты («у меня 500 Stars»).
2. **Каждый RemoteEvent проверяется:** тип и диапазон аргументов, rate limit, состояние игрока, права. Валидация описана в `docs/ARCHITECTURE.md`, раздел «Сеть».
3. **Данные игрока меняет только `PlayerDataService`** и сервисы через его API. Никто не пишет в `Profile.Data` напрямую.
4. **Никаких `SetAsync` / `GetAsync` для данных игрока.** Только через ProfileStore (session lock).
5. **Награды идемпотентны.** У каждой выдачи есть `grantId`; повторная выдача по тому же `grantId` — no-op.
6. **Без свободного чата.** Чат отключён (см. ARCHITECTURE.md → «Коммуникация»). Общение — только заранее заданные эмоции. Не добавлять текстовый ввод, который видят другие игроки.
7. **Весь видимый текст — через ключи локализации.** Никаких захардкоженных строк в UI. Английский — основной, русский — обязателен для каждого ключа.
8. **Mobile First.** Каждый экран сначала проверяется в эмуляторе телефона. Минимальный размер кнопки — см. ARCHITECTURE.md → «UI».
9. **Аналитика — только с сервера** через `TelemetryService` (обёртка над `AnalyticsService`).
10. Без лутбоксов, случайных платных наград и таймеров-давилок (детская аудитория, политики Roblox). Монетизация разрешена владельцем: донаты, косметика, удобства (пропуск этапа, пружинка и т.п.). Предметы с преимуществом не попадают в рекорды и медали (отдельный режим или пометка забега). Цены и описание — только в `docs/ECONOMY.md`.
11. Не копировать чужие игры, персонажей, модели, музыку, бренды.
12. Не хранить секреты, API-ключи, cookie в репозитории.
13. Не придумывать API Roblox. Сомневаешься — проверь Creator Hub (`create.roblox.com/docs`) и напиши, что проверено.

## Стиль кода

- Luau, `--!strict` в новых модулях; `--!nonstrict` допустим только с комментарием почему.
- Расширение файлов `.luau`. Серверные скрипты — `*.server.luau`, клиентские — `*.client.luau`, модули — `*.luau`.
- Один сервис/контроллер = один модуль с методами `Init()` (без yield) и `Start()`.
- Имена: `PascalCase` для модулей и типов, `camelCase` для локальных переменных и функций, `UPPER_SNAKE` для констант.
- Типы общих структур — в `src/shared/Types/`.
- Комментарии — на английском в коде; документация — на русском.

## Рабочий процесс

1. Перед крупным изменением — короткий план и список затрагиваемых файлов.
2. Маленькие коммиты, одно логическое изменение на коммит. Ветка на каждую задачу.
3. После изменений: `selene src tests/specs`, `stylua --check src tests`, `./tools/typecheck.sh`, `lune run tests/lune/run.luau`, `rojo build`.
4. Отчёт после задачи: что сделано, изменённые файлы, команды и их результат, известные проблемы, **что нужно проверить вручную в Studio**.
5. Никогда не писать «протестировано в Studio», если не запускал. Писать «проверено линтером / тестами», «требует ручной проверки».
6. Не удалять и не перезаписывать существующие файлы без проверки и объяснения.
7. Неоднозначность в безопасности, экономике, схеме данных или архитектуре — один конкретный вопрос до начала работы.
8. Изменение схемы данных = новая `SchemaVersion` + миграция + тест миграции + запись в `docs/DATA_SCHEMA.md`.
