> Платформа: Roblox · Roblox Studio + Luau
> Статус: pre-production, этап документации

## Что изменилось с версии 1.0

- Сформулирована главная особенность: **миниатюрный спортивный мир**.
- MVP сокращён до: Obstacle Dash + собственный клуб + Stars + сохранение.
- Маскоты, Target Tennis, приглашения друзей и сложные социальные функции перенесены за MVP.
- Зафиксирован набор инструментов: Rojo + Git + VS Code + Studio, плюс Rokit, Selene, StyLua, Luau LSP.
- Язык: английский основной, русский дополнительный; локализация с первого дня.
- Mobile First.
- Свободный чат отключается явно; вместо него — безопасные эмоции.
- Добавлены: ECONOMY.md, DATA_SCHEMA.md (с проектом DataStore), ARCHITECTURE.md, TEST_PLAN.md.
- Аналитика через `AnalyticsService`.

## 1. Видение

### Питч

**MINI CHAMPIONS** — дружелюбная многопользовательская игра, где ты размером с ластик. Огромный письменный стол — это стадион: беги по корешкам книг, перепрыгивай через карандаши, балансируй на линейке и строй свой спортивный клуб в углу стола из скрепок, стикеров и коробок от карандашей.

### Главная особенность

Игроки маленькие, а площадки построены на гигантских предметах повседневной жизни. Это даёт:
- **мгновенную узнаваемость** — ребёнок сразу понимает, что такое книга, карандаш, кружка;
- **естественную тематику обновлений** — каждое новое окружение (кухня, детская, сад, ванная) = новые площадки, препятствия и декор;
- **визуальную шутку**, которая хорошо смотрится на иконке и в превью;
- **простоту прототипа** — большинство предметов собирается из примитивов.

### Первое окружение — «Desk World» (письменный стол)

| Элемент | Как используется |
|---|---|
| Столешница | Центральная зона (хаб) и участки клубов |
| Стопки книг | Ступени, платформы, стены |
| Карандаши, ручки | Балки, мосты, вращающиеся препятствия |
| Линейка | Длинный узкий мост |
| Ластики | Пружинящие блоки |
| Точилка, степлер | Движущиеся препятствия (безопасные, без «опасности» в визуале) |
| Кружка, лампа | Ориентиры, освещение, финиш |
| Край стола | Падение = мягкий возврат на чекпоинт («приземлился на мягкий коврик») |

### Аудитория и принципы

Широкая семейная аудитория, включая детей. Принципы без изменений:
- понятно, что делать, в первые 30 секунд;
- первая награда за 2–3 минуты (см. ECONOMY.md);
- можно играть одному; присутствие других игроков добавляет ценность;
- прогресс без Robux;
- короткая сессия = завершённый результат;
- безопасная среда: без свободного чата, без торговли, без пользовательского контента.

## 2. MVP

**Цель:** небольшая цельная игра для закрытого теста. Мерило — понятность, стабильность и возвращаемость, а не объём контента.

### Входит в MVP

**Мир**
- Хаб на столешнице с точкой входа в Obstacle Dash.
- 6 участков клубов (по числу мест на сервере — требует подтверждения).
- Мягкие границы мира, возврат при падении.

**Obstacle Dash** (одна трасса — «Desk Dash»)
- 60–90 секунд для среднего игрока, 4 чекпоинта.
- Старт со стартовой площадки, отсчёт 3-2-1, таймер, финиш.
- Серверный учёт времени и порядка чекпоинтов.
- Медали Bronze/Silver/Gold по времени.
- Падение → возврат к последнему чекпоинту, таймер не сбрасывается.
- Выход игрока или таймаут → забег отменяется без награды.
- Несколько игроков могут бежать одновременно; таблица результатов текущего забега у финиша.

**Клуб**
- Личный участок на краю стола.
- 8 улучшений клуба за Stars (каждое видимо меняет участок) — см. ECONOMY.md.
- Уровень клуба = количество купленных улучшений + 1.
- Посторонний игрок может зайти на участок, но не может ничего изменить.

**Прогресс**
- Валюта Stars (единственная).
- Уровень игрока по опыту (XP).
- Личный рекорд и медали трассы.
- Короткое обучение (5 шагов).
- Сохранение через ProfileStore с блокировкой сессий.

**Интерфейс (Mobile First)**
- HUD: Stars, уровень, кнопка клуба, кнопка эмоций, кнопка настроек.
- Меню клуба (список улучшений, цены, кнопка покупки).
- Экран результата забега.
- Настройки: громкость музыки и звуков, язык (Auto / English / Русский), уменьшение движения.

**Коммуникация**
- Свободный текстовый чат отключён.
- Панель из 6 заранее заданных эмоций (иконка над головой + короткая анимация).

**Локализация**
- Все строки через LocalizationTable, английский + русский.

**Аналитика**
- Воронка обучения, экономические события, события прогресса через `AnalyticsService`.

### Не входит в MVP (перенесено)

| Функция | Куда |
|---|---|
| Маскоты (5 оригинальных) | Этап «После MVP-1» |
| Target Tennis | «После MVP-1» |
| Декор клуба отдельно от улучшений | «После MVP-1» |
| Задания (quests) | «После MVP-1» |
| Совместный старт матча / лобби | «После MVP-2» |
| Приглашения друзей | «После MVP-2» |
| Новые окружения (кухня и др.) | «После MVP-2» |
| Монетизация | Только после стабильных метрик |
| Торговля, кланы, UGC | Не планируется |

## 3. Технологии

| Инструмент | Роль | Оценка |
|---|---|---|
| Roblox Studio | Запуск, физика, UI, публикация | Обязателен |
| Rojo | Синхронизация файлов ↔ Studio | Обязателен |
| Git + GitHub | История и резервная копия | Обязателен |
| VS Code | Редактор | Обязателен |
| **Rokit** | Закрепляет версии CLI-инструментов в `rokit.toml`; одна команда `rokit install` на новой машине | **Рекомендую.** Современный преемник Aftman/Foreman, совместим с их файлами |
| **Selene** | Линтер Luau со стандартной библиотекой Roblox | **Рекомендую.** Ловит неиспользуемые переменные, затенение, устаревшие API |
| **StyLua** | Автоформатирование | **Рекомендую.** Убирает споры о стиле, удобно для AI-правок |
| **Luau LSP** | Типы, автодополнение, ошибки в VS Code | **Рекомендую.** Работает от `sourcemap.json` Rojo; без него `--!strict` малополезен |
| Wally | Пакеты | Только dev-зависимости (Jest-Lua) |
| Jest-Lua | Юнит-тесты внутри Roblox | Основной тест-фреймворк (TestEZ больше не развивается) |
| ProfileStore | Сохранения с session lock | Рекомендую, см. DATA_SCHEMA.md |

Подробности — `docs/ARCHITECTURE.md`.

## 4. Этапы

Оценки ориентировочные; каждая граница этапа — точка согласования.

### Этап 0 — документация и окружение
- [x] Аудит концепции (v1.0)
- [x] Обновлённый план, CLAUDE.md, ARCHITECTURE, ECONOMY, DATA_SCHEMA, TEST_PLAN
- [x] Согласование технических решений (раздел 7)
- [ ] Аудит локального окружения: Studio, Git, установка Rokit и инструментов
- [x] Каркас репозитория: `rokit.toml`, `default.project.json`, `selene.toml`, `stylua.toml`, `.vscode/`
- [ ] Отдельный тестовый опыт (experience) в Creator Hub для DataStore-тестов
- [ ] Пустой place запускается через `rojo serve`

**Готово, когда:** разработчик клонирует репозиторий, выполняет `rokit install` и `rojo serve`, и Studio показывает синхронизированное дерево.

### Этап 1 — вертикальный срез
Один сквозной путь на заглушках (серые блоки):
вход → загрузка профиля → обучение (минимальное) → Desk Dash → результат → Stars → покупка одного улучшения → выход → повторный вход → данные на месте.

Включает: `PlayerDataService` + ProfileStore, `CurrencyService`, `MinigameService` (Obstacle Dash), `RewardService`, `ClubService` (1 улучшение), сетевой слой с валидацией, отключённый чат, базовая локализация (ключи en+ru), первые события аналитики.

**Готово, когда:** цикл проходит без потери данных; клиент не может начислить себе Stars (проверено тестами из TEST_PLAN, раздел «Безопасность»).

### Этап 2 — полный MVP
- Все 8 улучшений, уровень клуба, XP и уровни игрока.
- Полное обучение (5 шагов).
- Медали, личный рекорд, таблица результатов забега.
- Эмоции.
- Полный UI, адаптированный под телефон, затем ПК.
- Все строки локализованы, проверка длины русских строк.
- Полная воронка аналитики.
- Арт: замена заглушек на low-poly предметы Desk World.

**Готово, когда:** выполнен Definition of Done (раздел 6).

### Этап 3 — закрытый тест
Небольшая группа тестировщиков. Наблюдаем: понимают ли цель без подсказок, доходят ли до первой покупки, возвращаются ли. Не собираем личные данные; с несовершеннолетними — только с согласия родителей и по правилам платформы.

### После MVP-1 (после данных закрытого теста)
Маскоты, Target Tennis (на тему стола: «Eraser Tennis» — рабочее название), отдельный декор, задания.

### После MVP-2
Совместные матчи и лобби, приглашения друзей, второе окружение (кухня), сезонные темы. Монетизация — только косметическая и только после стабильного удержания.

## 5. Аналитика и критерии успеха

Инструмент — `AnalyticsService` (воронки, экономика, прогресс, пользовательские события) + стандартные метрики Creator Analytics (D1, D7, время сессии).

Ключевые вопросы закрытого теста:
1. Какая доля доходит до первого финиша Desk Dash?
2. Какая доля покупает первое улучшение?
3. Где обрывается обучение?
4. D1 / D7 retention.
5. Среднее время сессии.
6. Частота ошибок (Error Report в Creator Hub).

Полная схема событий — `docs/ARCHITECTURE.md`, раздел «Аналитика». Ориентиры экономики — `docs/ECONOMY.md`.

Цикл улучшения: гипотеза → одно изменение → тест → сравнение метрик → запись вывода в `CHANGELOG.md`.

## 6. Definition of Done — MVP

- [ ] Новый игрок понимает, что делать, без внешних объяснений (наблюдение на тесте).
- [ ] Обучение проходится полностью на телефоне и на ПК.
- [ ] Desk Dash можно пройти; время и медаль считает сервер.
- [ ] Награда выдаётся ровно один раз за забег.
- [ ] Stars, XP, улучшения, рекорд и настройки сохраняются и восстанавливаются.
- [ ] Быстрый перезаход на другой сервер не дублирует и не теряет данные.
- [ ] Клиент не может начислить себе Stars или купить улучшение без денег (тесты безопасности пройдены).
- [ ] Свободный чат недоступен; эмоции работают.
- [ ] Все видимые строки есть на английском и русском; русский текст не обрезается.
- [ ] UI удобен на телефоне (эмулятор + минимум одно реальное устройство), затем на ПК.
- [ ] 2+ игрока одновременно: забеги и клубы не мешают друг другу.
- [ ] Нет критических ошибок в тестовых сценариях TEST_PLAN.
- [ ] События аналитики видны в Creator Hub.
- [ ] Описание, иконка, анкета зрелости контента подготовлены.
- [ ] Владелец проверил игру в Studio и одобрил публикацию.

## 8. Монетизация (после MVP, без изменений по сути)

Только необязательная косметика: декор, эффекты, варианты маскотов, эмоции. Без случайных платных наград, без продажи преимущества, без давления на детей. Через официальные механизмы Roblox с серверной обработкой `ProcessReceipt` и идемпотентностью по `PurchaseId`. Перед запуском — сверка с актуальными правилами Roblox.

## 9. Визуальный стиль

- Яркий stylized low-poly; предметы стола узнаваемы, но упрощены.
- Масштаб — главный приём: игрок маленький, предметы огромные. Камера и туман подчёркивают размер.
- Тёплый «настольный» свет от лампы, мягкие тени.
- Крупные контрастные интерактивные объекты; опасные зоны не выглядят страшно.
- UI: крупные кнопки, короткие подписи, иконки дублируют текст (важно для детей и для двух языков).
- Прототип — на заглушках из примитивов. Арт — только после подтверждения игрового цикла.
- Никаких реальных брендов на предметах (ручки, тетради без логотипов).
