# TEST_PLAN.md — план тестирования MVP

> Версия: 1.0 · Связано: `docs/ARCHITECTURE.md`, `docs/DATA_SCHEMA.md`, `docs/ECONOMY.md`

## 1. Уровни проверки

| Уровень | Чем | Кто запускает | Когда |
|---|---|---|---|
| L0. Статика | `selene src`, `stylua --check src`, Luau LSP (`--!strict`) | Claude Code / разработчик | Каждое изменение |
| L1. Юнит-тесты | Jest-Lua внутри Studio (тест-раннер), опционально Lune для чистой логики | Claude Code готовит, запуск в Studio — разработчик | Каждое изменение логики |
| L2. Сборка | `rojo build -o build/MiniChampions.rbxl` | Claude Code | Каждый коммит |
| L3. Studio: один игрок | Play / Play Here | Разработчик | Каждая задача |
| L4. Studio: несколько игроков | Test → Clients and Servers (сервер + 2–3 клиента) | Разработчик | Сеть, клуб, забеги, эмоции |
| L5. Эмулятор устройств | Studio Device Emulator (телефоны, планшет) | Разработчик | Каждый UI-экран |
| L6. Тестовый experience | Опубликованная приватная версия, реальный DataStore | Разработчик | Данные, перезаходы, аналитика |
| L7. Реальные устройства | Минимум 1 телефон Android или iOS + ПК | Разработчик | Перед закрытым тестом |
| L8. Закрытый тест | Группа тестировщиков | Владелец | Этап 3 |

**Честность отчётов:** Claude Code помечает каждый пункт как «проверено автоматически» (L0–L2) или «требует ручной проверки» (L3+). Запуск в Studio не заявляется, если его не было.

## 2. Юнит-тесты (L1)

Тестируется чистая логика без зависимостей от мира. Сервисы проектируются так, чтобы ядро логики было в чистых модулях.

| Модуль | Что проверяем |
|---|---|
| `Formulas` | Уровень из XP по формуле `50 + 25L` (граничные значения: 0, 74, 75, 5 700, сверх максимума); уровень клуба; медаль по времени (граница 55 000 / 55 001 мс) |
| `Config.Economy` | Сумма цен = 3 950; все цены > 0; все выдачи ≤ 500; ID улучшений уникальны и есть в локализации |
| `Validators` | Неверные типы, `NaN`, `inf`, `-0`, огромные числа, длинные строки, вложенные таблицы, лишние аргументы, `nil` |
| `RateLimiter` | Пропускает в лимите, режет сверх, восстанавливается со временем |
| `Migrations` | Каждая миграция N → N+1 на эталонных данных; цепочка 1 → текущая; данные новее кода — отказ |
| `Validate` (данные) | Зажатие значений вне диапазона, исправление некорректных типов, сохранение корректных данных без изменений |
| `RewardLogic` | Повтор `grantId` — no-op; разовая награда при установленном флаге — no-op; превышение лимита — отказ; кольцевой буфер ≤ 50 |
| `PurchaseLogic` | Индекс ≠ следующий — отказ; недостаточно Stars — отказ, баланс не изменился; успешная покупка списывает ровно цену |
| `DashStateMachine` | Все переходы раздела 8.1 ARCHITECTURE; недопустимые переходы игнорируются; награда только из `Finished`; повторный финиш не даёт второй награды |
| `Localization` | Каждый ключ из `Config` и кода есть в `UI.csv`; у всех строк заполнены `en` и `ru`; параметры `{x}` совпадают в обоих языках |
| `Plural.ru` | 1, 2, 5, 11, 12, 21, 22, 25, 101, 111 |

## 6. Критерии выхода для закрытого теста

- Все L0–L2 зелёные.
- Все сценарии разделов 3.1–3.6 пройдены, критичных дефектов нет.
- Регрессионный минимум пройден на тестовом experience.
- Хотя бы один прогон на реальном телефоне (U-06, P-01).

## 7. Классификация дефектов

| Уровень | Определение | Пример |
|---|---|---|
| Критический | Потеря/дублирование данных, начисление валюты клиентом, доступен свободный чат, игра не загружается | S-03 провален, X-01 провален, C-01 провален |
| Высокий | Основной цикл не проходится на одной из платформ | Нельзя нажать кнопку покупки на телефоне |
| Средний | Работает, но неудобно или неверно отображается | Обрезан русский текст |
| Низкий | Косметика | Неровная иконка |

Критические и высокие блокируют закрытый тест.
